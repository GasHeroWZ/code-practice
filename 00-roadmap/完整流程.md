# 做一道题的完整流程（从打开开始）

> 以 `stage1/01-is-prime` 为例。其他题只是名字不同，流程完全一致。
> 整个过程大约 20-40 分钟。

---

## 第 0 步：打开 VS Code 和文件夹

1. 打开 VS Code
2. 菜单 **文件 → 打开文件夹**
3. 选择 **`D:\个人\code-practice\00-roadmap`**
4. 左侧出现 `stage1` 到 `stage5` 五个文件夹

> ⚠️ 一定要打开 `00-roadmap` 这一层，不要只打开单个 `.c` 文件，也不要打开桌面上的文件。
> 只有打开这个文件夹，编译任务和调试配置才会生效。

---

## 第 1 步：找到题目，打开 main.c

左侧目录树展开：

```
00-roadmap
└─ stage1
   └─ 01-is-prime
      ├─ main.c          ← 点开这个
      ├─ case1.in
      ├─ case1.out
      └─ ...
```

**只点 `main.c`。** 其他文件都是测试用例，不要动。

---

## 第 2 步：读题（30 秒）

文件顶部有一段注释，三个信息：

```c
/* 题目: 判断一个整数是否为素数
 * 要求: 实现 IsPrime, n <= 1 返回 0; 是素数返回 1; 否则返回 0
 * 提示: 只需试除到 sqrt(n) 或 i*i <= n
 * 验收: judge.ps1 全部用例通过
 */
```

- **题目/要求**：要做什么
- **提示**：给你方法，不给代码
- 往下看还有一个 `main` 函数，**那是判题用的输入输出，不要改**

---

## 第 3 步：写代码

找到 `TODO`：

```c
int IsPrime(int n)
{
    /* TODO: 在这里实现 */
    (void)n;
    return 0;
}
```

把 `TODO` 那两行删掉，写你的实现。写完 **`Ctrl+S` 保存**（不保存等于没改）。

判断有没有保存：文件名标签上的**白点会消失**。

---

## 第 4 步：判题

### 方式 A：终端命令（推荐，信息最全）

按 **`` Ctrl+` ``** 打开终端（Ctrl + Tab 上面那个键），然后：

```powershell
cd D:\个人\code-practice\00-roadmap
.\judge.ps1 -Problem prime
```

> 只有第一次需要 `cd`。之后终端一直在这个目录，直接敲第二条即可。
> 按 `↑` 可以调出上一条命令，但**记得改关键字**（`prime` 换成 `table` 等）。

### 方式 B：VS Code 任务

`Ctrl+Shift+P` → 输入 `Tasks: Run Task` → 选 **「判这道题」**

它会自动识别你当前打开的文件属于哪道题。

### 方式 C：只编译不判题

`Ctrl+Shift+B` —— 只编译，看有没有语法错误。

## 第 5 步：读结果

### 通过了

```
  ===== 本次判题: 关键字 'prime'，共 1 题 =====

  --- stage1 ---
  [PASS] 01-is-prime  (6/6)
      输入 7  →  你的程序输出:
          yes
      输入 1  →  你的程序输出:
          no
```

`[PASS]` + `(6/6)` = 6 个用例全过。**这题做完了。**

### 没通过

```
  [FAIL] 01-is-prime  (3/6)
      输入 9
      期望: no
      实际: yes
```

逐层读：

| 信息 | 含义 | 该怎么办 |
|---|---|---|
| `(3/6)` | 过了 3 个 | 思路对，边界没处理 |
| `(0/6)` | 一个没过 | 逻辑不对，重新想 |
| `输入 9` | 是哪个输入出问题 | 用 9 手算一遍你的代码 |
| `期望 no / 实际 yes` | 正确答案 vs 你的输出 | 定位到具体分支 |

### 编译失败

```
  [编译失败] 02-gcd-lcm
      main.c:22:20: error: expected expression before 'int'
```

**编译错误要先修**，因为程序根本没生成，谈不上判题。看 `error:` 那一行和它指出的行号。

常见错误见文件末尾的对照表。

### 死循环

```
      问题: 程序没有正常结束（死循环）
      提示: 检查 while/for 后面有没有加 { }
```

判题器等 5 秒没等到程序结束，会强制终止并告诉你。按提示查花括号。

## 第 6 步：改 → 再判（这是核心循环）

```
改代码 → Ctrl+S → 判题 → 看差异 → 再改
```

一般 3-5 轮就能过一题。

**卡住超过 30 分钟就先跳过这题**，做下一题，第二天回来。C 语言很多概念是过一夜才通的。

卡住时可以看同目录上一层的 **`思路卡-stage1.md`**（伪代码级提示，不给代码）。

## 常见编译错误对照表

| 报错 | 原因 | 怎么改 |
|---|---|---|
| `implicit declaration of function 'printf'` | 没写 `#include <stdio.h>` | 文件第一行加上 |
| `expected ';' before '}'` | 少分号 | 往上一行找 |
| `'i' undeclared` | 变量没定义 | `for (int i = 0; ...)` |
| `expected expression before 'int'` | 调用函数时写了参数类型 | `Gcd(a,b)` 而不是 `Gcd(int a,int b)` |
| `too few arguments to function` | 参数个数不对 | 对照函数定义 |
| `undefined reference to 'xxx'` | 声明了但没实现 | 补上函数体 |
| 程序卡住不结束 | `while`/`for` 缺花括号 | 循环体超过一行必须加 `{ }` |

## 一道题的完整时间线

| 阶段 | 时间 |
|---|---|
| 打开文件、读题 | 2 分钟 |
| 写代码 | 10-20 分钟 |
| 判题 + 调试 | 5-15 分钟 |
| 提交到 GitHub | 30 秒 |

**一天做 1-2 题就够，关键是每天都有产出。**

## 一条容易忽视的规则：**文件名用英文**

中文文件名会导致生成的 `.exe` 名字变成乱码（实测 `模板.exe` 会变成 `Ä£°å.exe`），
`cc` 命令会因此判定「编译失败」。

| 可以 | 不要 |
|---|---|
| `table.c` | `void PrintTable(int n).c` |
| `p1.c` | `我的练习.c` |
| `swap.c` | `1. 交换.c` |

规则：**只用英文字母、数字、下划线**，不带空格、括号、中文、点号开头。
