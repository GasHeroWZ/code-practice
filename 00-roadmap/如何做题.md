# 怎么用这套练习（新手操作手册）

> 你只需要动一个文件：每道题里的 `main.c`。
> 其他文件都别碰，尤其是 `judge.ps1` 和 `case*.in` / `case*.out`。

---

## 一、先搞清楚这里有几种文件

打开 `D:\个人\code-practice\00-roadmap\stage1\01-is-prime\`，你会看到：

| 文件 | 是什么 | 你要动它吗 |
|---|---|---|
| `main.c` | **题目和你的代码** | ✅ 只改这个 |
| `case1.in` | 第 1 个测试用例的**输入** | ❌ 别改 |
| `case1.out` | 第 1 个用例的**期望输出** | ❌ 别改 |
| `case2.in` / `case2.out` | 第 2 个用例 | ❌ 别改 |
| `a.exe` | 判题时临时编译出的程序 | ❌ 忽略它，可删 |
| `judge.ps1`（在上一层） | 判题器，自动编译 + 比对 | ❌ 别改 |

**逻辑关系**：判题器把 `case1.in` 里的内容喂给你的程序，看你输出的是不是 `case1.out` 里写的。对了算通过，不对就告诉你差在哪。

2. 菜单 `文件 → 打开文件夹`
3. 选择 `D:\个人\code-practice\00-roadmap`
4. 左侧会出现 `stage1` 到 `stage5` 五个文件夹

以后每次做题都从这里进。

## 三、第二步：看题

展开 `stage1 → 01-is-prime`，点开 `main.c`，你会看到这样一段：

```c
/* 题目: 判断一个整数是否为素数
 * 要求: 实现 IsPrime, n <= 1 返回 0; 是素数返回 1; 否则返回 0
 * 提示: 只需试除到 sqrt(n) 或 i*i <= n
 * 验收: judge.ps1 全部用例通过
 */
int IsPrime(int n)
{
    /* TODO: 在这里实现 */
    (void)n;
    return 0;
}
```

**三个信息都在注释里**：

- `题目/要求`：这题要干什么
- `提示`：给方法，不给答案
- `TODO`：你要填的地方

下面还有一个 `main` 函数，**那是判题用的输入输出，不用改**。它负责读输入、调用你写的 `IsPrime`、打印结果。

所以你的任务永远只有一个：**把 `TODO` 那段换成真正的代码**。

---

## 四、第三步：写代码

把 `TODO` 那行删掉，写上你的实现。比如第一题写完大概是这样：

```c
int IsPrime(int n)
{
    if (n <= 1) return 0;
    for (int i = 2; i * i <= n; ++i) {
        if (n % i == 0) return 0;
    }
    return 1;
}
```

**注意**：`(void)n;` 这行是占位用的（防止"变量未使用"警告），你用了 `n` 之后就可以删了。

## 五、第四步：判题（最关键的一步）

### 打开终端

VS Code 里按 **`` Ctrl+` ``**（Ctrl 加反引号，在 Tab 键上面），底部会弹出一个终端。

### 进入判题目录

```powershell
cd D:\个人\code-practice\00-roadmap
```

### 跑判题器

**判一题**（推荐，快）：

```powershell
.\judge.ps1 -Problem prime
```

**判一个阶段**：

```powershell
.\judge.ps1 -Stage 1
```

**判全部**（16 题，稍慢）：

```powershell
.\judge.ps1
```

### 看结果

**通过**时会显示：

```
===== stage1 =====
  [PASS] 01-is-prime  (6/6)
```

`6/6` 表示 6 个测试用例全过。

**没通过**时会显示：

```
===== stage1 =====
  [FAIL] 01-is-prime  (3/6)
      用例 case1.in
        期望: yes
        实际: no
```

这段信息非常有价值，逐层读：

| 信息 | 含义 |
|---|---|
| `(3/6)` | 6 个用例过了 3 个 → **大方向对，但某些情况没处理** |
| `(0/6)` | 一个都没过 → **逻辑根本不对，回去重想** |
| `期望: yes` | 正确答案是什么 |
| `实际: no` | 你的程序输出了什么 |

第 1 题过 3 个没过 3 个，就是经典的**边界问题**：你知道 7 是素数，但忘了 1 不是素数、2 是素数。

## 六、第五步：改 → 再判，循环

改完 `main.c` **记得按 `Ctrl+S` 保存**，然后重新跑判题命令。

VS Code 里按 `↑` 方向键可以调出上一条命令，不用重敲。

**这个循环就是全部**：改代码 → 保存 → 判题 → 看差异 → 再改。

一般 3-5 轮就能过一题。

## 八、常见报错对照表

Compile 阶段的报错（判题器会显示 `[编译失败]` 并列出前 5 行）：

| 报错 | 真实原因 | 怎么改 |
|---|---|---|
| `implicit declaration of function 'xxx'` | 函数名拼错，或没声明就用 | 检查拼写；C 语言里先声明后使用 |
| `expected ';' before '}'` | 少分号 | 往上找最近的语句 |
| `'i' undeclared` | 变量没定义 | `int i = 0;` |
| `too few arguments to function` | 调用时参数个数不对 | 对照函数定义 |
| `invalid conversion from 'int*' to 'int'` | 指针用错了 | 该用 `*p` 的地方用了 `p` |
| `undefined reference to 'xxx'` | 声明了但没实现（链接阶段报） | 补上函数体 |

运行结果不对（判题器显示差异）：

| 现象 | 常见原因 |
|---|---|
| 输出完全对但判 FAIL | 多了空格、少了换行（`printf("%d", x)` vs `printf("%d\n", x)`） |
| 部分用例过 | 边界没处理（0、1、负数、长度为 1） |
| 输出全是 0 | `TODO` 没改，或者改了但没保存 |
| 输出是乱码 | 源文件编码问题，用 VS Code 右下角改成 UTF-8 |

## 九、每天怎么安排

**推荐节奏（每天 40-60 分钟）**：

```
1. 听 1 讲视频（30 分钟）
2. 打开对应阶段的题，读注释（5 分钟）
3. 自己写 TODO（15-20 分钟，不许先搜答案）
4. 判题，看差异，改（5-10 分钟）
5. 过了就 commit（1 分钟）
```

**卡住超过 30 分钟就先跳过**，做下一题，第二天回来。C 语言很多概念是"过一夜就通了"。

## 十一、三条铁律

1. **不许先看答案。** 卡了就看 `main.c` 顶部的 `提示:`，那是给方法的，不是给代码的。
2. **不许改测试用例。** `case*.in/out` 改了就等于自己给自己判及格，没意义。
3. **不许跳过 FAIL 的题。** 16 题全 PASS 才代表 C 语言这部分真的会了。

## 十二、遇到问题怎么办

把这两样东西贴给我：

1. 你的 `main.c` 完整内容
2. 终端里判题器的输出（`[FAIL]` 那段）

我能直接看出是思路问题、边界问题还是语法问题。

**但先自己卡 30 分钟**——那 30 分钟才是真正在学 C 语言。
